# podcast-bot — две дорожки в Telegram, готовый выпуск на выходе

Бот для подкаста на двоих, которые записываются удалённо, каждый на своё устройство. Оба присылают боту свои дорожки, бот сам их синхронизирует, вырезает подготовку до выпуска и разговоры после него, обрабатывает звук, ставит заставки и делает таймкоды. Сначала он показывает минутное превью, а после подтверждения присылает обоим готовый MP3 и текст для публикации.

Работает на Raspberry Pi 5 в Docker. Устройство кода для разработчиков и агентов описано в [AGENTS.md](AGENTS.md), планы — в [ROADMAP.md](ROADMAP.md).

## Что получается

- **MP3** 192 кбит/с, громкость −16 LUFS, пик не выше −1,5 dBTP, с заставками, обложкой и главами внутри файла: их показывают Apple Podcasts, Overcast и Pocket Casts.
- **Подпись для канала** в формате выпусков: `#12: название` и таймкоды (первый — сразу после заставки).
- **Описание** для площадок: 2–4 предложения и главы.
- **Расшифровка** по ролям (`transcript.txt`), субтитры (`transcript.srt`), главы в формате Podcasting 2.0 (`chapters.json`).

## Как выходит выпуск

Каждый ведущий работает с ботом в своём чате. Закреплённая **карточка выпуска** у обоих одинаковая и обновляется вживую. Внизу чата всегда видна строка статуса, например `🎙 №12 · Аня ✅ · Боря ⏳`.

1. **Открыть выпуск.** После записи нажмите «➕ Записали выпуск №12» или просто пришлите файл. Номер растёт сам, пропуск недели ничего не ломает.
2. **Прислать дорожки.** Каждый присылает свою: аудио, видео, голосовую, архив zip/7z/rar (бот возьмёт аудио изнутри) или ссылку на Google Drive. До 2 ГБ. Лучше отправлять **файлом** (📎 → Файл), чтобы Telegram не пережимал. На файл бот ставит реакции: 👀 принял, ⚡ распаковываю, 👌 готово.
3. **30 секунд на замену.** Когда обе дорожки на месте, в карточке идёт отсчёт: можно прислать другой файл или нажать «✋ Подождать».
4. **Сборка.** Карточка показывает этапы с прогрессом и время готовности, у каждого по его часам.
   ```
   ✅ синхронизация · сдвиг -0.6 с
   ✅ расшифровка · 412 реплик
   ✅ начало, конец и главы · 20 глав
   ⚙️ превью ▰▰▰▰▱▱▱▱ 52%
   готово ≈ 19:42
   ```
5. **Превью** — заставка и первая минута. По нему проверяют синхронизацию, громкость и эффекты. Кнопки:
   - «✂️ Начало/конец» — сдвиг в секундах: `+3` (начать позже), `0 -5` (закончить раньше);
   - «🎛 EQ» — включить или выключить эквалайзер;
   - «🎚 Мягче / Жёстче» — компрессор: 1,5 → 2 → 3 → 4 → 6:1;
   - «⏪ / ⏩ ±100 мс» — ручная поправка синхронизации второго голоса;
   - «🎙 Аня: …» / «🎙 Боря: …» — профиль микрофона каждого ведущего (листается по кругу; последний — «авто»: EQ подтягивает голоса к общему тональному балансу);
   - «🔇 Шумодав» 0 → 6 → 8 → 12 дБ (если задан `rnnoise_model` — просто «нейро / выкл»), «〰 Де-эссер» (свистящие), «📈 Выравн.» — выравнивание громкости по ходу выпуска, если ведущий отдалялся от микрофона.

   Правка пересобирает только превью, за секунды. Когда всё в порядке, кто-то один нажимает **«✅ Собирай полный»**. Без этого полный выпуск не собирается.
6. **Готовый выпуск** (~8 минут) приходит обоим: MP3 с подписью и архив. В карточке видны первые и последние реплики и объяснение, почему выпуск начинается и заканчивается именно там. Правки на этом этапе: обрезка по времени готового MP3, главы (скопировать, поправить, прислать), **вырез куска** (см. ниже), EQ, пересборка. Любая правка сбрасывает одобрения.

   **🪚 Вырезать кусок** — для сбоя связи, дубля, оговорки. Кнопка просит промежуток по времени готового MP3 (как в таймкодах поста): `55:39-56:09` или `55:39-56:09 сбой связи` (слова после времён — пометка). Бот подсказывает места, похожие на сбой («прервалось», «скажи ещё раз», «вырежем»). Края он сам сдвигает в ближайшие паузы, потому что стык — кроссфейд 0,4 с, и в нём не должно быть чьей-то речи; смысл при этом держите вы: вырезайте так, чтобы реплики сходились. Вырезается обе дорожки сразу, главы и расшифровка сдвигаются. К MP3 и архиву, которые придут после пересборки, приписывается «✂️ Вырезано 29 с (…) · стык на 56:02». «↩️ Вернуть вырез» отменяет последний.
7. **Одобрение.** Каждый нажимает «✅ Одобряю», внизу видно `Аня ✅ · Боря ⏳`. Когда одобрили оба, бот добавляет выпуск в свой RSS-фид (`FEED_URL`, его забирают Apple Podcasts, Spotify, Яндекс Музыка и др.) и публикует в Telegram-канал (`PUBLISH_CHAT`, бот — админ канала) и присылает ссылку; если канал не задан — напоминает переслать вручную, подпись уже готова.

**🔔 Синхросигнал** — кнопка меню бота «🔔 Синхро» (слева от поля ввода) открывает мини-приложение. Оно работает только у ведущих. Свист в точно известный момент по часам бота позволяет совместить дорожки с точностью до сотых секунды, без него синхронизация идёт по разговору.
1. До записи оба открывают «Синхро». В заголовке номер выпуска («выпуск №12»), ниже оба ведущих: кто в сети, кто готов, насколько точно сверены часы, сколько сигналов уже записано.
2. «🔈 Проверить звук» — свист сразу и только у себя, ничего не записывает. Громкость устройства — средняя или выше (страница не может её менять), звук на динамик рядом с микрофоном.
3. Каждый жмёт «Я готов». Включаете запись.
4. Когда оба готовы, любой жмёт «Сигнал обоим · начало»: через пару секунд свист звучит у обоих одновременно. В конце записи, до остановки — «Сигнал обоим · конец». Бот подтверждает: «Выпуск №12: синхросигнал №1 (начало) записан · часы ±4 мс».

Часы показываются двумя цифрами: «часы ±4 мс (сеть 150 мс)». Сеть — сколько идёт запрос до бота, часы — реальная точность сверки (задержка сети вычитается). Если сигнал всё же разойдётся с разговором больше чем на 0,3 с, бот возьмёт разговор и напишет об этом в карточке. Пишете в Диктофон на iPhone — открывайте «Синхро» с другого устройства (ноутбук рядом): свист на том же iPhone может прервать запись.

Под дисплеем — **таймер записи**: идёт с первого сигнала («начало») и останавливается на втором («конец»). Его держит бот, поэтому если связь пропадёт (на дисплее «ОФЛАЙН») или приложение закроется, после переоткрытия таймер и сигналы будут на месте — нужно только снова нажать «Готов».

**💡 Темы** — идеи для следующих выпусков. Добавляются в боте: кнопка «💡 Тема» внизу → текст; второй ведущий сразу видит, кто что предложил. Смотреть и голосовать («огонь / можно / мимо») — во вкладке «Темы» мини-приложения. Там же: тема ⇄ заметка (заметка — мысль или ссылка, тема — то, что можно обсуждать), «в выпуск» (короткий список на ближайшую запись), «обсудили» (запоминает номер выпуска). Наверху — то, за что ты ещё не голосовал.

**Напоминание** приходит одно: на следующий день в 13:00 по часам получателя, если второй дорожки так и нет или превью никто не проверил.

**Команды:** `/status` — карточка, `/intro`, `/outro`, `/cover` — заменить заставки и обложку, `/help`.

## Что бот делает со звуком

| Шаг | Как |
|---|---|
| Синхронизация | Если во время записи нажимали «🔔 Синхро» — по синхросигналу (точность часов телефонов, ~10–30 мс). Иначе: хлопки через звонок не работают: каждый слышит другого с задержкой. Бот ищет сдвиг, при котором вы реже всего говорите одновременно, а ответ одного идёт сразу после реплики другого. Паузы ответа уравниваются в обе стороны. Дрейф часов двух устройств меряется по всей записи и компенсируется. Если голос собеседника слышен в чужом микрофоне, синхронизация идёт по общему звуку с точностью до миллисекунды. |
| Начало и конец | LLM читает расшифровку и находит настоящее начало: последнее приветствие, после которого уже нет подготовки (хлопков, «как начинаем?», пробных дублей, «раз, два, три»). Конец — последнее прощание. Точное время берётся по словам. |
| Чистка | Срез ниже 70 Гц, шумодав, мягкий гейт в паузах (порог по шуму каждой дорожки). |
| Голоса | Свой эквалайзер для каждого голоса до сведения — по профилю микрофона (`mic_profiles`) или «авто». По желанию — де-эссер и выравнивание громкости. |
| Громкость | Каждая дорожка к −20 LUFS, сведение, компрессор (по умолчанию порог −10 дБ, 3:1), итог −16 LUFS, лимитер с 4-кратной передискретизацией. |
| Заставки | Конец вступления затухает за секунду, первое слово звучит сразу за ним. Финальная заставка начинается сразу после последнего слова. |
| Текст | Расшифровка — AssemblyAI, каждая дорожка своим каналом, поэтому кто говорит, известно точно. Название, описание и главы — LLM (DeepSeek V4.1 Flash через OpenRouter; если не ответил — запасная модель, затем AssemblyAI LLM Gateway). |

## Установка

Нужны Docker с Docker Compose и Linux-сервер (проверено на Raspberry Pi 5, arm64; на amd64 тоже работает). Для синхросигнала нужен ещё аккаунт Tailscale.

### 1. Код, папки и секреты

```bash
git clone <адрес репозитория> podcast-bot && cd podcast-bot
cp .env.example .env                       # заполнить, см. ниже
cp -r secrets.example secrets             # заполнить, см. ниже
mkdir -p /srv/podcast-data                 # та же папка, что DATA_DIR в .env
cp settings.example.json /srv/podcast-data/settings.json
# бот работает не от root: как uid 101 (пользователь локального Bot API) с группой HOST_GID из .env
sudo chown -R 101:$(id -g) /srv/podcast-data && chmod -R u+rwX,g+rwX,o-rwx /srv/podcast-data
chmod 750 secrets && chmod 640 secrets/*
```

**Секреты** — файлы в `secrets/` (шаблоны с заглушками — в `secrets.example/`), права 640: читают владелец и группа `HOST_GID`, под которой работает бот. В git настоящие не попадают. Вместо файлов можно задать переменные окружения `BOT_TOKEN`, `ASSEMBLYAI_API_KEY`, `OPENROUTER_API_KEY` (удобно на облачном сервере или без Docker):

| Файл | Содержимое | Откуда |
|---|---|---|
| `bot_token` | токен бота, одной строкой | @BotFather |
| `telegram_api.env` | две строки: `TELEGRAM_API_ID=123456` и `TELEGRAM_API_HASH=0123abcd…` | https://my.telegram.org → API development tools. Нужен локальному Bot API: облачный отдаёт ботам файлы только до 20 МБ |
| `assemblyai_key` | ключ AssemblyAI | assemblyai.com; час записи в двух каналах — около $0,3–0,5 |
| `openrouter_key` | ключ OpenRouter | openrouter.ai; около 1 цента за выпуск |

### 2. Значения установки — `.env`

Шаблон с пояснениями — [`.env.example`](.env.example). `docker compose` читает `.env` сам; в git он не попадает.
- `PEOPLE="id:Имя:Часовой/Пояс[:ж],…"` — ведущие; `ж` — женский род в текстах мини-приложения («Готова?»). Порядок важен: первый — канал A, второй — канал B. Бот отвечает только им; чужому пишет его Telegram ID, чтобы его можно было добавить.
- `PODCAST_NAME`, `START_N` (номер последнего вышедшего выпуска), `TZ`, `DATA_DIR` (папка данных на хосте).
- `HOST_GID` — группа хоста, которой доступны данные и секреты (обычно ваша: `id -g`).
- `PUBLISH_CHAT` — канал для публикации после одобрения (`@канал` или `-100…`); пусто — без автопубликации.
- `FEED_URL` — публичный адрес веб-сервера бота для RSS-фида (обычно = `WEBAPP_URL`); пусто — без фида. Перенос с прежнего хостинга: скачать его `feed.xml`, обложку и аудио как `<guid>.mp3` в одну папку → `python3 feed.py import <папка> --data <DATA_DIR> --base <FEED_URL>`; выпуски сохраняют guid, поэтому на площадках не задвоятся. Дальше — сменить адрес фида в кабинете каждой площадки.
- `WEBAPP_URL` и `TS_HOSTNAME` — для синхросигнала (шаг 5); без них бот работает, просто без него.
- Время отсчёта до старта и час напоминаний — `GRACE_SECONDS`, `REMIND_HOUR` прямо в `docker-compose.yml`.

### 3. Настройки звука и текста — `$DATA_DIR/settings.json`

Пример — [`settings.example.json`](settings.example.json); все ключи и значения по умолчанию — `DEFAULTS` в `podcast.py`. Главные:
- `mic_profiles` — именованные профили микрофонов (строки фильтров ffmpeg), `track_profile` — профиль каждого ведущего по порядку `PEOPLE` (или `"авто"`). В превью профиль меняется кнопкой. Профили в примере — отправная точка; подогнать под свои микрофоны помогут `tools/miccheck.py` и `tools/eqcheck.py`;
- `deesser`, `dynaudnorm`, `denoise_nr` — де-эссер, выравнивание громкости, сила шумодава (тоже кнопками в превью);
- `rnnoise_model` — путь к модели RNNoise (`.rnnn`): тогда каждая дорожка чистится нейросетевым шумодавом вместо обычного (убирает шипение между словами заметно лучше, но может подкрасить голос — сначала послушайте минуту своего голоса). Модели не входят в репозиторий: `curl -O https://raw.githubusercontent.com/GregorR/rnnoise-models/master/beguiling-drafter-2018-08-30/bd.rnnn` в `$DATA_DIR/models/`, в настройках путь внутри контейнера (`/data/models/bd.rnnn`); кнопка шумодава в превью тогда переключает «нейро / выкл» без градаций.
- `spelling` — свои замены слов в расшифровке (например, как распознаётся название подкаста);
- `comp_threshold_db`, `comp_ratio`, `target_lufs`, `bitrate`.

### 4. Запуск

```bash
docker compose up -d --build telegram-bot-api podcast-bot
docker compose logs -f podcast-bot
```

Если бот раньше работал через обычный (облачный) Bot API, перед первым запуском с локальным сервером его нужно разлогинить, один раз:
```bash
curl -X POST "https://api.telegram.org/bot$(cat secrets/bot_token)/logOut"
```

Заставки и обложку проще всего прислать боту командами `/intro`, `/outro`, `/cover`.

### Быстрый старт без Tailscale

Синхросигнал — единственное, чему нужен внешний https. Без него бот работает полностью: оставьте `WEBAPP_URL` пустым и запускайте только два контейнера (шаг 4) — синхронизация пойдёт по разговору. Минимум для первого выпуска: `bot_token`, `telegram_api.env`, `PEOPLE` и `DATA_DIR` в `.env`; без ключей AssemblyAI и OpenRouter не будет расшифровки и глав, а обрезка пойдёт по тишине.

### 5. Синхросигнал (необязательно)

Мини-приложение Telegram открывается только по https, поэтому бот выставляет его наружу через отдельный узел Tailscale с Funnel (контейнер `podcast-tailscale`). Наружу видна только страница мини-приложения; что именно открыто — в [SECURITY.md](SECURITY.md).
1. В админке Tailscale должны быть включены MagicDNS и HTTPS-сертификаты, а в политике доступа — Funnel для узла (атрибут `funnel`).
2. `docker compose up -d podcast-tailscale` и войти по ссылке из `docker compose logs podcast-tailscale` — или положить ключ авторизации в `secrets/ts_authkey` и задать в compose `TS_AUTHKEY: "file:/secrets/ts_authkey"`. Подводные камни входа — в AGENTS.md, раздел «Синхросигнал».
3. У узла в админке — **Disable key expiry**, иначе через 180 дней кнопка перестанет открываться.
4. Вписать `https://<TS_HOSTNAME>.<tailnet>.ts.net/` в `WEBAPP_URL` и `docker compose up -d podcast-bot` — бот сам поставит кнопку меню «🔔 Синхро». Публичная DNS-запись для нового узла иногда появляется через полчаса.

### Приватность

Записи выпусков отправляются в AssemblyAI (расшифровка), расшифровка — в OpenRouter (LLM находит начало и конец, делает главы, название и описание). Без ключей этих сервисов бот работает, но без расшифровки и глав, а обрезает по тишине.

## Без бота

`podcast.py` работает как обычная программа. Нужны Python 3.12, ffmpeg и `pip install -r requirements.txt`.

```bash
export ASSEMBLYAI_API_KEY=…  OPENROUTER_API_KEY=…            # без них — без расшифровки и глав
export PODCAST_SETTINGS=./settings.json                      # свои настройки (необязательно)
python3 podcast.py run A.wav B.m4a --names Аня Боря --work ep12   # полная сборка
python3 podcast.py render ep12 --start 0:45 --end 58:10            # пересобрать с другой обрезкой
python3 podcast.py analyze A.wav B.m4a                             # только синхронизация
```

Необязательные переменные окружения бота (по умолчанию подходят для docker-compose): `BOT_TOKEN` / `BOT_TOKEN_FILE`, `ASSEMBLYAI_API_KEY` / `AAI_KEY_FILE`, `OPENROUTER_API_KEY` / `OPENROUTER_KEY_FILE`, `BOT_API`, `HTTP_PORT`, `DATA`, `PODCAST_SETTINGS`, `GRACE_SECONDS`, `REMIND_HOUR`, `KEEP_TRACKS_DAYS`.

## Тесты

```bash
pip install -r requirements.txt pytest
pytest -q tests          # синтетические дорожки: синхронизация, поиск сигнала, разбор времени, подпись мини-приложения, карточка
```

## Советы для записи

- Каждый пишет свою дорожку в наушниках, чтобы голос собеседника не попадал в микрофон.
- Рекордер с направленными микрофонами держите в 15–20 см ото рта и чуть сбоку: вблизи сильно раздувается бас.
- На iPhone: Настройки → Приложения → Диктофон → Качество звука → **Без потерь**. «Сжатый» режим — это 64 кбит/с и обрыв всего, что выше 16 кГц.
- Хлопать перед началом не нужно: бот синхронизирует по самому разговору и сам вырежет подготовку.
